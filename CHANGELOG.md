# История релизов Hikari Secretary

Общая история платформы: бот, backend, miniapp и развёртывание.
Компоненты имеют собственные версии; состав платформы фиксируется
коммитами сабмодулей в этом репозитории.

## 2026-11-22 · Бот 1.0.1, Backend 0.4.0 и Miniapp 0.2.0

- Участники открывают «Панель клуба» в личном чате и могут просматривать
  встречи и анонсы, управлять записью и напоминанием, отмечать посещение,
  заполнять профиль и оставлять отзывы. Администраторы переключают режим
  из бокового меню.
- Member API проверяет подписанные данные Telegram и ограничивает личные
  операции учётной записью участника. Production nginx направляет запросы
  Member API в backend.

## 2026-11-22 · Backend 0.3.5 и Miniapp 0.1.5

- Bot API отдаёт ближайшие мероприятия со статусом записи участника и ссылкой
  на анонс, если она известна. Участник может изменить напоминание для
  действующей регистрации.
- В разделе ИИ кнопка «Отменить выход поста» снимает с отправки последний
  поставленный в очередь ИИ-пост независимо от даты и способа запуска.
  Настройка автогенерации хранится в PostgreSQL. Автогенерацию можно выключить
  отдельной кнопкой на следующие дни с сохранением сегодняшнего поста.
- Кнопка «Поставить новую генерацию в очередь» запускает подготовку материала
  с сохранёнными настройками и доступна при выключенной автогенерации.
  Для ожидающего поста сохраняются время и цели отправки.
- Сохранённый черновик открывается по ссылке из бота. В предпросмотре
  мероприятия отображается одна зелёная кнопка «Зарегистрироваться»
  на всю ширину сообщения.
- В боковом меню указаны дата выпуска и версии бота, backend и miniapp.

## 2026-11-22 · Бот 1.0.0

С версии 1.0.0 бот переходит в сопровождение.

- В Telegram раздел «Ближайшие мероприятия» объединяет открытые встречи
  и личные записи. В «Управлении записью» участник может настроить напоминание
  или отменить регистрацию. Возврат к списку обновляет текущее сообщение.
  При наличии ссылки кнопка «Анонс» открывает опубликованное сообщение.
- В административном меню бота остались создание публикации, список
  активных мероприятий с участниками и отменой, очередь и переход в miniapp.
  Архив, отзывы, статистика и управление ИИ доступны в miniapp. Бот
  продолжает доставлять автоматически подготовленные материалы.
- Новый или пересланный материал сохраняется как черновик до предпросмотра.
  Бот предлагает открыть его в панели или продолжить публикацию прямо в чате.
  В локальном Compose ссылка на черновик доступна для копирования.

## 2026-11-21 · Backend 0.3.4 и Miniapp 0.1.4

- Кнопка «Заменить последнюю генерацию» в разделе ИИ позволяет повторить
  последнее задание с ошибкой или обновить его запланированный материал
  до начала доставки с сохранением времени отправки и целей.
- Backend хранит версии сохранённых материалов ИИ и учитывает их при
  следующей генерации. В miniapp можно увидеть число версий и открыть
  прежние материалы в карточке задания.

### Развёртывание

- Подготовлены таймеры для еженедельного копирования PostgreSQL и медиа
  и для отправки журналов контейнеров в начале каждого часа по UTC
  в закрытый S3-совместимый бакет. Журналы хранятся 30 дней.
  После успешной загрузки ротация оставляет последнюю проверенную копию
  за каждую ISO-неделю с копиями в скользящем окне 365 суток.
  Настройка VPS и восстановление описаны в [руководстве по архивированию в S3](docs/s3-archive.md).

## 2026-11-20 · Backend 0.3.3 и Miniapp 0.1.3

- **Backend.** Admin API возвращает карточку задания истории ИИ по ID
  и поддерживает сортировку по статусу связанной публикации. Генератор
  получает указание писать название темы на японском.
- **Miniapp.** История ИИ показывает статусы генерации и публикации.
  Из списка можно открыть карточку материала с предпросмотром сообщения
  и форматированием Telegram, в том числе для архивных заданий без связанной
  публикации. В карточке мероприятия добавлены отступы между элементами.
- **CI/CD.** Корневой GitHub Actions проверяет зафиксированные ревизии
  компонентов. Подготовлен ручной выпуск из `main` с доставкой готовых
  образов из GHCR по digest и применением миграций на сервере.
- **Развёртывание.** В `bot-local` можно включить генерацию ИИ-материалов
  через DeepSeek и настроить автоматическую публикацию в тестовую цель.
  Параметры задаются в корневом `.env`.

Подробности в [истории backend](https://github.com/jpegMushrum/hikari-secretary-backend/blob/main/CHANGELOG.md)
и [истории miniapp](https://github.com/jpegMushrum/hikari-secretary-miniapp/blob/main/CHANGELOG.md).

## 2026-11-19 · Backend 0.3.2 и Miniapp 0.1.2

- **Backend.** Admin API сортирует отфильтрованные списки по всем колонкам
  мероприятий, черновиков, участников, публикаций, отзывов и истории ИИ.
- **Miniapp.** Нажатие на заголовок любой колонки сортирует список, а
  повторное нажатие меняет направление сортировки. В меню над профилем
  администратора показаны дата релиза и версии бота, backend и miniapp.

Подробности в [истории backend](https://github.com/jpegMushrum/hikari-secretary-backend/blob/main/CHANGELOG.md)
и [истории miniapp](https://github.com/jpegMushrum/hikari-secretary-miniapp/blob/main/CHANGELOG.md).

## 2026-11-19 · Backend 0.3.1 и Miniapp 0.1.1

- **Развёртывание.** Обычный запуск production применяет миграции PostgreSQL и запускает
  приложения. Снимок SQLite и перенос данных вынесены в отдельный профиль
  `legacy-import`. Запись в PostgreSQL требует явного `--apply`.
- **Backend.** Администратор может найти мероприятие, черновик, участника
  или отзыв по ID. Поиск отзывов по названию встречи или данным автора
  сочетается с точными фильтрами из карточек. Для обновления действующего
  стенда с PostgreSQL новых миграций и повторного импорта SQLite не требуется.
- **Miniapp.** В таблицах появились отдельные скрываемые колонки ID,
  а в списке участников встречи — время регистрации и отмены. Порядок
  колонок меняется в прокручиваемом меню «Колонки». Обновлены мобильные
  фильтры, переходы внутри разделов и ссылки на собеседников в Telegram.
- **Проверка.** Поиск проверен на PostgreSQL 18, интерфейс — сборкой,
  автоматическими тестами и HTTP-проверкой локального стенда. Проверка
  жестов и отображения в Telegram на iPhone остаётся открытой.

Подробности в [истории backend](https://github.com/jpegMushrum/hikari-secretary-backend/blob/main/CHANGELOG.md)
и [истории miniapp](https://github.com/jpegMushrum/hikari-secretary-miniapp/blob/main/CHANGELOG.md).

## 2026-11-18 · Backend 0.3.0 и Miniapp 0.1.0

Платформа запущена на PostgreSQL. Участники продолжают пользоваться ботом,
администраторы получили miniapp. Началось тестирование на сервере.

### Backend 0.3.0

- Go API стал владельцем профилей, мероприятий, регистраций, посещаемости,
  отзывов и очередей публикаций.
- Добавлен admin API мероприятий, публикаций, медиа, отзывов и статистики,
  а также настроек ИИ и истории тем.
- Бот и miniapp используют общую бизнес-логику. Административный доступ
  проверяется по Telegram initData и роли, запросы бота — по service token.
- Реализован единый список мероприятий и черновиков с серверными фильтрами,
  сортировкой и пагинацией.
- Подготовлены миграции, импорт SQLite → PostgreSQL, OpenAPI и тесты с PostgreSQL.
- Мигратор отделён от настроек Telegram и ИИ: для запуска нужен только DATABASE_URL.

### Miniapp 0.1.0

- Административные разделы: мероприятия, участники, отзывы и ИИ.
- Тёмная и светлая темы, красный акцент клуба, логотип 光 и левое меню.
- Таблицы с поиском, фильтрами, сортировкой, пагинацией, скрытием и
  перестановкой колонок с сохранением предпочтений.
- Сценарий «сообщение боту → черновик → предпросмотр → настройка → публикация».
- Предпросмотр rich messages и фотографий, выбор целей и времени отправки.
- Карточка мероприятия со статистикой, участниками и Telegram-ссылками.
- Цветные статусы регистрации, сокращённый статус, колонки гражданства и ИТМО.

### Интеграция бота и запуск

- Бот переведён на backend API; работа через команды и кнопки сохранена.
- Добавлены персональная кнопка miniapp для администраторов и переход
  из карточки черновика в его настройки.
- Оставлены два самостоятельных Compose-стека: production и bot-local.
- Production включает nginx с HTTPS и настраиваемыми портами; внутренний
  API и PostgreSQL не публикуются наружу.
- Перед импортом сохраняется отдельный снимок SQLite, включая WAL-записи.
  Повторный импорт не перезаписывает изменения, сделанные в PostgreSQL.

Старые черновики и завершённые публикации не входят в импорт и сохраняются
в исходном SQLite. Пользовательский режим miniapp и переработка репостов
остаются в [плане развития](docs/miniapp-plan.md).
