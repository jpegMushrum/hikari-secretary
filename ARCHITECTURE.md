# Архитектура Hikari Secretary

## Слои приложения

`app/bot.py` — композиционный корень. Он создаёт зависимости, подключает доменные
обработчики к `aiogram.Router` и управляет жизненным циклом фонового процесса.
Бизнес-логики в этом модуле быть не должно.

`app/handlers/` содержит входные сценарии Telegram, разделённые по доменам:

- `core.py` — `/start`, `/help` и маршрутизация deep-link;
- `inbox.py` — приоритетная маршрутизация универсального входящего контента;
- `publications.py` — черновики, цели публикации, расписание и медиагруппы;
- `registrations.py` — анкета пользователя, мероприятия, регистрации и посещаемость.

`app/workers/` содержит фоновые процессы. `scheduler.py` забирает из SQLite
готовые к выполнению задания, публикует записи и отправляет напоминания.

`app/runtime.py` хранит явно передаваемые зависимости и только временное состояние
диалогов. Долговечное состояние всегда находится в SQLite, поэтому перезапуск
процесса не теряет очередь, регистрации и напоминания.

`app/access.py` отвечает за общие правила доступа, а `app/presentation.py` — за
чистые функции представления и понятные пользователю тексты ошибок.

`app/db.py` — единая граница хранения данных. Обработчики не выполняют SQL и не
знают структуру таблиц. Изменения схемы вносятся только версионированными
миграциями из `migrations/`.

`app/publishers.py` изолирует API целевых площадок от сценариев создания
публикации.

## Направление зависимостей

```text
main -> bot -> handlers / workers
                  |       |
                  +--- AppContext --- config / db / Telegram Bot
                  |
                  +--- access / presentation / keyboards / formatting
```

Доменные модули не импортируют композиционный корень и не создают глобальные
экземпляры бота или базы. Это позволяет тестировать их через подмену зависимостей
и добавлять новые домены без изменения существующих сценариев.

## Порядок обработки сообщений

Команды и callback-запросы регистрируются раньше `InboxHandlers`. Входной
маршрутизатор сначала проверяет активный сценарий регистрации или редактирования
профиля и только после этого передаёт сообщение домену публикаций. Там ввод
времени обрабатывается раньше создания нового черновика. Порядок между доменами
закреплён отдельными тестами.

## Добавление нового домена

Для независимой функции следует создать отдельный модуль в `app/handlers/` и,
если ей нужен фоновый цикл, отдельный worker в `app/workers/`. Долговечные данные
добавляются миграцией и методами слоя хранения; временное состояние — отдельной
структурой в `RuntimeState`. В `SecretaryBot` остаются только создание объекта и
одна строка его регистрации.
