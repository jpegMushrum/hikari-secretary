# Hikari Secretary

Telegram-бот для публикаций и регистрации участников мероприятий в Telegram-каналах и чатах.

## Возможности

- несколько администраторов по Telegram ID;
- любое количество целей Telegram;
- публикация в конкретные топики Telegram-супергрупп;
- текст, ссылки, одиночные изображения, альбомы и Telegram Rich Messages;
- регистрация пользователей на мероприятие кнопкой под публикацией;
- приватные анкеты и списки участников, доступные только администраторам;
- личный список мероприятий и отмена регистрации;
- индивидуальное время напоминания для каждого участника;
- постраничные списки мероприятий и учёт посещаемости после них;
- сохранение форматирования Telegram;
- единый настраиваемый часовой пояс;
- очередь в SQLite, отмена и автоматические повторные попытки;
- результат отдельно по каждой цели.

Видео, документы, регулярные публикации, изменение и удаление уже опубликованных записей, веб-панель и статистика намеренно не поддерживаются.

## Прототип генерации тем

В проекте подготовлен сервис генерации материалов для разговорного клуба через
DeepSeek. Он запрашивает тему разговора, отдельную тему лексики, вопросы, словарь
и грамматические конструкции в JSON-формате. Все успешно созданные разговорные и
лексические темы сохраняются и передаются в контекст следующих запросов, чтобы
снижать количество повторов.

Для последующего включения провайдера укажите `DEEPSEEK_API_KEY` в `.env`.
Модель и адрес API настраиваются параметрами `DEEPSEEK_MODEL` и
`DEEPSEEK_BASE_URL`. Уровень конкретной генерации администратор выбирает в панели
кнопками от `N5` до `N1`; при первом открытии выбран `N3`. Объём материала
задаётся только через
`AI_TOPIC_QUESTION_COUNT`, `AI_TOPIC_VOCABULARY_COUNT` и
`AI_TOPIC_GRAMMAR_COUNT`.

`AI_TOPIC_TARGET_KEY` должен содержать ключ ровно одной цели из `targets.json`.
ИИ-сервис ставит публикации только в неё. Та же цель умеет сопоставлять входящие
`chat_id` и `message_thread_id`, поэтому при добавлении слушателя его область
работы не придётся конфигурировать отдельно.

`AI_TOPIC_AUTO_PUBLISH_TIME` задаёт ежедневное время автоматической публикации в
формате `ЧЧ:ММ` и часовом поясе `TIMEZONE`. Пустое значение отключает автоматику.
Следующая тема генерируется сразу, как только планировщик видит будущую дату, и
заранее появляется в очереди. В очереди администратор может открыть Rich Message,
перегенерировать его, исправить отдельным пожеланием или отменить. После наступления
времени планировщик создаёт задание на следующий день. Автоматическая генерация
использует тот же уровень JLPT и комментарий, которые администратор сохранил в
разделе ИИ.

Для будущего чтения сообщений у выбранной цели должен быть числовой `chat_id`;
если нужен конкретный топик форума, укажите также `message_thread_id`.

В панели администратора функции разделены на «Мероприятия и публикации» и «ИИ».
В разделе ИИ администратор может сгенерировать материал, проверить предпросмотр,
выбрать уровень JLPT, добавить пожелание к теме, перегенерировать результат либо
опубликовать. Уровень и комментарий сохраняются до следующего изменения и также
используются автоматическими публикациями. Только подтверждённая ручная тема ставится в
очередь выбранного таргета и добавляется в историю использованных тем.

ИИ-публикации отправляются как Telegram Rich Messages: тема и вопросы видны сразу,
а полезная лексика и грамматика находятся в отдельных сворачиваемых блоках.
Промпт требует точного соответствия выбранному JLPT, а структурированный ответ
содержит уровень и отклоняется, если модель вернула другую маркировку. Для N3
отдельно требуется средняя сложность: объяснение причин, сравнение, выражение
мнения и конструкции N3 вместо одних базовых шаблонов N5-N4.

## Подготовка

1. Создайте Telegram-бота через BotFather и добавьте его администратором в канал. В чате дайте ему право отправлять сообщения и изображения.
2. Скопируйте `.env.example` в `.env` и заполните значения.
3. Скопируйте `targets.example.json` в `targets.json` и укажите цели.

Для цели можно использовать `@username` публичного Telegram-канала или числовой ID чата. Для отправки в определённый топик суперчата добавьте цели поле `message_thread_id`.

## Запуск

```text
docker compose up -d --build
```

Перед запуском бота Compose автоматически запускает одноразовый контейнер `migrate`. Он применяет недостающие версии схемы SQLite и только после успешного завершения запускает `bot`. Для существующей базы перед миграцией автоматически создаётся согласованная резервная копия в `data/backups`.

Проверить миграции отдельно:

```text
docker compose run --rm migrate
```

Просмотр состояния:

```text
docker compose logs -f bot
```

Остановка:

```text
docker compose down
```

База, резервные копии миграций и загруженные изображения сохраняются в локальной папке `data`. Не запускайте несколько экземпляров контейнера одновременно с одной SQLite-базой.

## Использование

Администратор отправляет боту в личные сообщения текст, фотографию с подписью, альбом или Rich Message. Структура Rich Message — заголовки, списки, разделители, форматирование и premium emoji — сохраняется при публикации. Затем администратор выбирает цели и при необходимости включает регистрацию. Для мероприятия бот отдельно запрашивает название, время начала и время окончания. Название и дата используются в пользовательских и административных списках независимо от текста публикации. После этого публикацию можно отправить сразу или запланировать.

Команда `/start` открывает панель администратора с кнопками создания публикации, просмотра очереди, управления мероприятиями и перехода в пользовательский интерфейс. Telegram-меню команд настраивается автоматически при каждом запуске бота; у пользователей в нём всегда доступна кнопка `/start`, а администраторы видят расширенный набор команд.

В Rich Message кнопка регистрации встраивается непосредственно в содержимое поста. В обычных публикациях бот добавляет ссылку регистрации в текст или подпись. Inline-клавиатура к публикации не прикрепляется, поэтому Telegram сохраняет штатные комментарии канала.

Пользователь может нажать кнопку «Зарегистрироваться» под публикацией либо открыть личные сообщения с ботом и выбрать «Записаться на мероприятие». Бот постранично покажет доступные будущие мероприятия. Имя и фамилия, гражданство РФ и статус студента ИТМО заполняются один раз в разделе «Настройка профиля» и доступны только администраторам. Если профиль ещё не заполнен, бот предложит настроить его при первой регистрации. Для каждого мероприятия пользователь отдельно выбирает время напоминания или отказывается от него. Команда `/events` постранично показывает активные регистрации пользователя и позволяет отменить их до начала мероприятия. Через `/profile` можно посмотреть и изменить все данные профиля; изменения сразу отображаются администраторам в списках регистраций.

Бот сохраняет актуальные Telegram username, имя и фамилию профиля. Администратор видит `@username`, а при его отсутствии — отображаемое имя Telegram; числовой Telegram ID сохраняется всегда.

Напоминание отправляется один раз перед началом мероприятия в выбранный пользователем момент. Доступные варианты задаются в `.env` параметром `REMINDER_OPTIONS_MINUTES` через запятую: например, `30,60,120,360,1440` означает варианты за 30 минут, 1, 2, 6 и 24 часа. Варианты, время которых уже прошло, при регистрации не предлагаются.

После окончания бот спрашивает зарегистрированного пользователя, посетил ли он мероприятие. Ответ и анкета видны администраторам в приватной панели `/registrations`. Списки активных и прошедших мероприятий имеют пагинацию. Там же администратор может отменить незавершённое мероприятие с подтверждением; зарегистрированные участники получат личное уведомление. Отменённые мероприятия в панели не отображаются.

Команда `/queue` показывает администраторам ближайшие публикации и позволяет их отменить.

Время вводится как `ДД.ММ.ГГГГ ЧЧ:ММ`. Для даты текущего или следующего года также принимается `ДД.ММ ЧЧ:ММ`.

## Как узнать ID администраторов и чатов

Утилита `app.resolve_ids` определяет публичные Telegram-цели по ссылкам или коротким именам без остановки основного бота:

```text
docker compose run --rm bot python -m app.resolve_ids --telegram @channel_name https://t.me/group_name
```

Утилита выводит готовый `chat_id`.

Если Telegram-чат приватный и у него нет публичного `@username`, остановите основной бот и запустите эту же утилиту в режиме прослушивания:

```text
docker compose stop bot
docker compose build bot
docker compose run --rm bot python -m app.resolve_ids --listen
```

Затем:

- отправьте сообщение в нужном групповом чате — утилита покажет ID пользователя и чата;
- отправьте команду внутри нужного топика — утилита дополнительно покажет `message_thread_id`;
- добавьте бота в канал как администратора и опубликуйте тестовую запись — утилита покажет ID канала;
- событие добавления бота в чат также покажет ID этого чата.

Результаты выводятся в терминале, а в личном или групповом чате бот дополнительно отвечает найденными ID. Для завершения нажмите `Ctrl+C`, после чего снова запустите основной сервис:

```text
docker compose up -d bot
```
