# Telegram ID и топики

Каждая цель в `targets.json` получает понятный `key`, название и Telegram
идентификатор. Для публичного канала можно использовать `@username`, для чата
или приватного канала — числовой `chat_id`.

```json
{
  "telegram": [
    {
      "key": "main_channel",
      "name": "Основной канал",
      "chat_id": "@channel_username"
    },
    {
      "key": "club_topic",
      "name": "Топик разговорного клуба",
      "chat_id": -1001234567890,
      "message_thread_id": 42
    }
  ]
}
```

`message_thread_id` нужен только для форумного супергруппового топика. Последнее
число в ссылке вида `https://t.me/c/<chat>/<message>` — это ID сообщения. Оно
совпадает с `message_thread_id`, только если ссылка ведёт на корневое сообщение
этого топика; по ссылке на обычный ответ ID темы надёжно не определить. Всегда
получайте `message_thread_id` утилитой из сообщения, отправленного внутри нужного
топика.

## Публичные каналы и чаты

Утилита определяет публичные цели по `@username` или ссылке:

```bash
docker compose run --rm bot python -m app.resolve_ids --telegram \
  @channel_name https://t.me/group_name
```

## Приватные чаты, каналы и топики

Остановите основной контейнер, чтобы один и тот же бот не получал обновления
одновременно с утилитой:

```bash
docker compose stop bot
docker compose run --rm bot python -m app.resolve_ids --listen
```

Затем:

1. Отправьте сообщение в нужном групповом чате — утилита покажет ID пользователя
   и чата.
2. Отправьте команду внутри нужного топика — утилита дополнительно покажет
   `message_thread_id`.
3. Для канала добавьте бота администратором и опубликуйте тестовую запись —
   утилита покажет ID канала.

Завершите утилиту `Ctrl+C`, затем верните основной бот:

```bash
docker compose up -d bot
```
