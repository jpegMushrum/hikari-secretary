# Каталог use cases

Каталог согласован 2026-10-28. В действующей платформе участники пользуются
ботом, а администраторам доступен также miniapp 0.1.2. Одна операция может
иметь оба входа и использовать общие бизнес-правила backend.

## Акторы

| Актор | Описание |
| --- | --- |
| Участник | Пользователь Telegram, который регистрируется, получает уведомления и оставляет отзывы. |
| Администратор | Для команд бота ID должен входить в `ADMIN_IDS`, для Admin API — в `ADMIN_TELEGRAM_IDS`. |
| Bot adapter | Python-сервис, принимающий Telegram updates и вызывающий внутренний Bot API. |
| Delivery worker | Компонент бота, отправляющий подтверждённые задания в Telegram. |
| Scheduler | Бот периодически запрашивает у backend готовые доставки, напоминания и запросы посещения. Планировщик автоматической генерации ИИ работает в backend. |

## Правила каталога

- UI не определяет use case: callback, команда бота, Mini App-форма и worker
  могут быть разными входами одной операции.
- API передаёт даты со смещением. Бот использует `TIMEZONE`, miniapp показывает даты по Москве.
- Команды, которые могут быть повторены callback-ом, ретраем worker или сетью,
  используют идемпотентный ключ либо уникальное бизнес-ограничение.
- Ограничения в таблице ниже применяются в application layer и подтверждаются
  ограничениями PostgreSQL, а не только скрытием кнопок.

## Контракт списков Mini App

Все административные таблицы Mini App используют единый постраничный контракт.
Администратор выбирает размер страницы `10`, `20` или `30`; значение по
умолчанию — `10`, верхняя граница — `30`. Изменение фильтра, сортировки или
размера страницы всегда сбрасывает номер страницы на первую.

Номер и размер страницы хранятся в параметрах URL. Видимость и порядок
колонок сохраняются в браузере отдельно для каждой таблицы и администратора.

```http
GET /api/v1/admin/people?page=9&page_size=20&sort=visits&order=desc&is_itmo_student=true
```

```json
{
  "items": [],
  "page": {
    "number": 9,
    "size": 20,
    "total_items": 154,
    "total_pages": 8
  },
  "sort": {"field": "visits", "order": "desc"},
  "filters": {"is_itmo_student": true}
}
```

Параметры `page`, `page_size`, `sort`, `order` и каждый фильтр валидируются
до вызова репозитория. API принимает только объявленные значения, не получает
из клиента имена SQL-колонок, SQL-фрагменты или произвольный JSON-фильтр.
Репозиторий использует параметризованные запросы. При равном значении
основного поля сортировки порядок определяет ID, а в объединённом списке
мероприятий и черновиков — тип записи и ID.

| Таблица | Разрешённые фильтры | Разрешённые сортировки |
| --- | --- | --- |
| Люди | ФИО, Telegram-имя, username, внутренний или Telegram ID, гражданство РФ, студент ИТМО | ID, ФИО, число посещений и отзывов, последнее посещение, гражданство, ИТМО |
| Мероприятия и черновики | статус, период начала, поиск по названию или ID | ID, начало, название, дата создания, статус, число регистраций и посещений |
| Участники мероприятия | статус регистрации, гражданство РФ, студент ИТМО, нужен пропуск | ID, ФИО, Telegram username, время регистрации и отмены, статус, посещение, нужен пропуск, гражданство, ИТМО |
| Отзывы | тип, мероприятие, автор, период, поиск по мероприятию, автору или ID отзыва | ID, текст, мероприятие, автор, время создания |
| Публикации | статус, Telegram-цель, источник, период публикации | ID, текст, статус, назначенное время публикации, дата создания |
| История ИИ | статус задания | ID, название, назначенное время, статус, число попыток |

В miniapp 0.1.2 заголовки колонок запускают серверную сортировку по всей
отфильтрованной выборке. Мероприятия и связанные с ними черновики
выводятся без дублирования в объединённом списке. Реальные имена
параметров и варианты сортировки приведены в [Admin API](https://github.com/jpegMushrum/hikari-secretary-backend/blob/main/docs/admin-api.md).

В невыпущенном обновлении история ИИ показывает статус связанной публикации
отдельно от статуса задания. Таблица сортируется по статусу публикации, а
материал открывается в отдельной карточке.

## Люди, мероприятия и отзывы

| ID | Use case | Актор | Основные правила |
| --- | --- | --- | --- |
| IAM-01 | Аутентифицировать Mini App | Администратор | Проверить подпись и срок `initData`, затем роль. Реализовано в backend. |
| IAM-02 | Аутентифицировать bot adapter | Bot adapter | Проверить отдельный сервисный токен. В production внутренний API доступен только внутри сети Docker. |
| PPL-01 | Синхронизировать Telegram-идентичность | Bot adapter | При каждом действии сохранять числовой Telegram ID, актуальные username и display name. |
| PPL-02 | Создать или изменить профиль | Участник | Одно поле ФИО, гражданство РФ, статус студента ИТМО. Профиль принадлежит участнику. |
| PPL-03 | Настроить предложения отзывов | Участник | Переключатель влияет только на автоматические предложения. Ручной отзыв настройку не меняет. |
| EVT-01 | Создать мероприятие | Администратор | Название, начало и окончание; начало раньше окончания; максимум пять активных мероприятий. Публикация — отдельный объект, а не ID мероприятия. |
| EVT-02 | Просмотреть мероприятия | Участник, администратор | Участник видит единый список ближайших встреч со своим статусом и действием для каждой встречи. Администратор видит активные встречи в боте и архив в miniapp. |
| REG-01 | Зарегистрироваться | Участник | Мероприятие активно, профиль заполнен, одна актуальная регистрация на пару участник–мероприятие. Повтор не создаёт дубликат. |
| REG-02 | Настроить напоминание | Участник | Выбрать допустимое смещение или отказаться при записи. До начала встречи настройку можно изменить из карточки записи. |
| REG-03 | Отменить регистрацию | Участник | Разрешено до начала мероприятия; сохраняется время отмены. Повторная регистрация заменяет актуальное время регистрации. |
| EVT-03 | Отменить мероприятие | Администратор | Только активное мероприятие; все зарегистрированные участники получают задание уведомления. |
| EVT-04 | Просмотреть участников | Администратор | Постраничный список с регистрациями, отменами, посещениями, профильными признаками и ссылками в Telegram. |
| EVT-05 | Отправить напоминание | Scheduler + delivery worker | Напоминание отправляется по сохранённому времени. Изменение интервала позволяет запланировать новое напоминание, пока до него есть время. Недоступность пользователя не должна останавливать остальные задания. |
| ATT-01 | Запросить посещение | Scheduler + delivery worker | После окончания мероприятия спросить зарегистрированного участника один раз. |
| ATT-02 | Зафиксировать посещение | Участник | Варианты «был» и «не был» сохраняются с временем ответа. Только «был» может инициировать автоматический отзыв. |
| FB-01 | Предложить отзыв | Delivery worker | Только посетившему участнику и только при включённой настройке. «Нет» ничего не отключает; «Никогда» выключает будущие предложения. |
| FB-02 | Оставить отзыв о мероприятии | Участник | Связан с посещённым мероприятием; ввод можно пропустить без записи. |
| FB-03 | Оставить общий отзыв | Участник | Не связан с мероприятием и не меняет настройку автоматических предложений. |
| FB-04 | Просмотреть отзывы | Администратор | Постраничная таблица и просмотр полного текста; видны автор, время и мероприятие или признак общего отзыва. |
| STATS-01 | Просмотреть статистику людей | Администратор | Постраничный список с числом посещений и отзывов, датой последнего посещения и профильными признаками. Число отзывов включает связанные и общие. |

### Критические инварианты первого среза

1. Время регистрации, отмены, ответа о посещении и отзыва никогда не
перезаписывается отображаемой строкой времени; хранится исходный timestamp.
2. Регистрация уникальна по `event_id + person_id`; её состояние меняется
явно, а не удалением строки.
3. Общий отзыв имеет `event_id = NULL`; это не ошибка и не ссылка на последнее
мероприятие.
4. Проверка прав выполняется до чтения чужих данных. Наличие Telegram ID само
по себе не делает пользователя администратором.
5. Сохранённая отметка посещения не откатывается, если отправка предложения
отзыва в Telegram завершилась ошибкой.

## Публикации и доставка Telegram

| ID | Use case | Актор | Основные правила |
| --- | --- | --- | --- |
| PUB-01 | Создать черновик | Администратор | Текст, ссылки, фотография, альбом или Telegram Rich Message. Видео, документы и опросы вне scope. |
| PUB-02 | Выбрать Telegram-цели | Администратор | Канал, чат или конкретный топик супергруппы; целью владеет конфигурация deployment. |
| PUB-03 | Опубликовать или запланировать | Администратор | Немедленная либо отложенная публикация в `TIMEZONE`; максимум пять ожидающих публикаций. |
| PUB-04 | Отменить ожидающую публикацию | Администратор | Не изменяет уже опубликованные сообщения. Массовое удаление и редактирование не входят в scope. |
| PUB-05 | Доставить публикацию | Delivery worker | Отдельный результат на каждую Telegram-цель, retries для временных ошибок, уведомление создателю. |
| PUB-06 | Завершить публикацию | Delivery worker | После всех доставок сформировать итоговое уведомление. Медиа сохраняются для предпросмотра и истории. |

Бот принимает новый или пересланный материал, сохраняет черновик и предлагает
открыть его в miniapp или остаться в чате. Оба интерфейса показывают
предпросмотр и дают настроить регистрацию, цели и время отправки.
Сценарий репостов предстоит согласовать. [План miniapp](miniapp-plan.md).

## Материалы разговорного клуба

| ID | Use case | Актор | Основные правила |
| --- | --- | --- | --- |
| LRN-01 | Настроить генерацию | Администратор | В miniapp выбрать JLPT N5–N1 и необязательное пожелание. |
| LRN-02 | Подготовить материал | Scheduler | Тема, вопросы, лексика и грамматика валидируются до сохранения. |
| LRN-03 | Просмотреть историю генерации | Администратор | В miniapp доступны версии материалов, состояние задания и статус связанной публикации. |
| LRN-05 | Ежедневно подготовить материал | Scheduler | При настроенной и включённой автопубликации валидный материал ставится в очередь. |
| LRN-06 | Поддерживать историю разнообразия | Модуль материалов | История влияет на prompt, но не вводит жёсткий запрет на повтор лексики или грамматики. |
| LRN-07 | Управлять автогенерацией | Администратор | Выключение сохраняет сегодняшний пост и останавливает ежедневную генерацию на следующие дни. |
| LRN-08 | Поставить новую генерацию в очередь | Администратор | Miniapp запускает генерацию с сохранёнными настройками даже при выключенной автогенерации. Если в очереди есть ИИ-пост, доступный для замены, его материал обновляется после успешной генерации. Иначе новый материал публикуется в ближайшее время по расписанию или сразу после генерации, если время не настроено. |
| LRN-09 | Отменить выход поста | Администратор | Miniapp снимает с отправки последний ИИ-пост в очереди независимо от даты и способа запуска. Действие доступно, пока все доставки ожидают отправки или повторной попытки. Расписание автогенерации сохраняется. |

Ошибка AI, в том числе превышение длины ответа, не создаёт пустую публикацию:
она остаётся ошибкой generation job, получает retry policy и уведомление
администраторам после исчерпания попыток.

Обязательное ручное одобрение ежедневного материала относится к целевой
модели. [Архитектура платформы](architecture.md).

Backend готовит материалы по расписанию. Бот доставляет публикации и сообщает
администраторам об окончательных сбоях.

## Будущая граница

`Language Practice` будет обрабатывать японскую орфографию только для точно
настроенной пары `chat_id + message_thread_id`. Это отдельный use case и не
является обработкой каждого сообщения Telegram или частью `Learning Content`.
