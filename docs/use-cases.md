# Каталог use cases

**Статус:** согласован 2026-10-28. Это функциональный контракт платформы, а
не описание экранов или HTTP endpoints. Один и тот же use case может вызываться
из Telegram-бота и из Mini App.

## Акторы

| Актор | Описание |
| --- | --- |
| Участник | Пользователь Telegram, который регистрируется, получает уведомления и оставляет отзывы. |
| Администратор | Пользователь Telegram с ролью администратора. Временно разрешается allowlist из конфигурации; далее — постоянная роль backend. |
| Bot adapter | Python-сервис, принимающий Telegram updates и вызывающий внутренний Bot API. |
| Delivery worker | Компонент бота, отправляющий подтверждённые задания в Telegram. |
| Scheduler | Backend worker, запускающий отложенные и периодические задачи. |

## Правила каталога

- UI не определяет use case: callback, команда бота, Mini App-форма и worker
  могут быть разными входами одной операции.
- Все даты хранятся в UTC и показываются в `TIMEZONE` проекта.
- Команды, которые могут быть повторены callback-ом, ретраем worker или сетью,
  используют идемпотентный ключ либо уникальное бизнес-ограничение.
- Ограничения в таблице ниже применяются в application layer и подтверждаются
  ограничениями PostgreSQL, а не только скрытием кнопок.

## Контракт списков Mini App

Все административные таблицы Mini App используют единый постраничный контракт.
Администратор выбирает размер страницы `10`, `20` или `30`; значение по
умолчанию — `10`, верхняя граница — `30`. Изменение фильтра, сортировки или
размера страницы всегда сбрасывает номер страницы на первую.

Выбранный размер может храниться локально в Mini App отдельно для каждого
администратора. Backend не обязан сохранять эту UI-настройку в профиле.

```http
GET /api/v1/admin/people?page=1&page_size=20&sort=visits&order=desc&is_itmo_student=true
```

```json
{
  "items": [],
  "page": {
    "number": 1,
    "size": 20,
    "total_items": 154,
    "total_pages": 8
  },
  "sort": {"field": "visits", "order": "desc"},
  "filters": {"is_itmo_student": true}
}
```

Параметры `page`, `page_size`, `sort`, `order` и каждый фильтр валидируются
до вызова репозитория. API принимает только объявленные значения, не получает
из клиента имена SQL-колонок, SQL-фрагменты или произвольный JSON-фильтр.
Репозиторий использует параметризованные запросы и добавляет постоянный
tie-breaker (`id`) к каждой сортировке, чтобы строки с одинаковым основным
значением не перемещались между страницами.

| Таблица | Разрешённые фильтры | Разрешённые сортировки |
| --- | --- | --- |
| Люди | поисковая строка ФИО/Telegram, гражданство РФ, студент ИТМО | ФИО, число посещений, последнее посещение |
| Мероприятия | статус, период начала, поиск по названию | начало, название, дата создания |
| Участники мероприятия | статус регистрации, гражданство РФ, студент ИТМО, нужен пропуск | ФИО, время регистрации, необходимость пропуска |
| Отзывы | мероприятие, общий/связанный отзыв, автор, период | время создания |
| Публикации | статус, Telegram-цель, источник, период публикации | время публикации, дата создания |

Таблица публикаций относится к следующему срезу, но использует тот же
контракт. Новая сортировка или фильтр требует явного добавления в API-контракт,
application layer, индекс PostgreSQL при необходимости и теста.

## Первый перенос: люди, мероприятия и отзывы

| ID | Use case | Актор | Основные правила |
| --- | --- | --- |
| IAM-01 | Аутентифицировать Mini App | Администратор | Проверить подпись и срок `initData`, затем роль. Реализовано в backend. |
| IAM-02 | Аутентифицировать bot adapter | Bot adapter | Использовать отдельный сервисный токен; будущий внутренний API не публикуется наружу. |
| PPL-01 | Синхронизировать Telegram-идентичность | Bot adapter | При каждом действии сохранять числовой Telegram ID, актуальные username и display name. |
| PPL-02 | Создать или изменить профиль | Участник | Одно поле ФИО, гражданство РФ, статус студента ИТМО. Профиль принадлежит участнику. |
| PPL-03 | Настроить предложения отзывов | Участник | Переключатель влияет только на автоматические предложения. Ручной отзыв настройку не меняет. |
| EVT-01 | Создать мероприятие | Администратор | Название, начало и окончание; начало раньше окончания; максимум пять активных мероприятий. Публикация — отдельный объект, а не ID мероприятия. |
| EVT-02 | Просмотреть мероприятия | Участник, администратор | Участник видит свои будущие регистрации; администратор — активный обзор и постраничный архив. |
| REG-01 | Зарегистрироваться | Участник | Мероприятие активно, профиль заполнен, одна актуальная регистрация на пару участник–мероприятие. Повтор не создаёт дубликат. |
| REG-02 | Выбрать напоминание | Участник | Выбрать допустимое смещение или отказаться; выбор принадлежит регистрации. |
| REG-03 | Отменить регистрацию | Участник | Разрешено до начала мероприятия; сохраняется время отмены. Повторная регистрация заменяет актуальное время регистрации. |
| EVT-03 | Отменить мероприятие | Администратор | Только активное мероприятие; все зарегистрированные участники получают задание уведомления. |
| EVT-04 | Просмотреть участников | Администратор | Пагинация, сортировка по ФИО, времени регистрации и необходимости пропуска; показываются регистрация/отмена/посещение и профильные признаки. |
| EVT-05 | Отправить напоминание | Scheduler + delivery worker | Не более одного напоминания для выбранной регистрации; недоступность пользователя не должна останавливать остальные задания. |
| ATT-01 | Запросить посещение | Scheduler + delivery worker | После окончания мероприятия спросить зарегистрированного участника один раз. |
| ATT-02 | Зафиксировать посещение | Участник | Варианты «был» и «не был» сохраняются с временем ответа. Только «был» может инициировать автоматический отзыв. |
| FB-01 | Предложить отзыв | Delivery worker | Только посетившему участнику и только при включённой настройке. «Нет» ничего не отключает; «Никогда» выключает будущие предложения. |
| FB-02 | Оставить отзыв о мероприятии | Участник | Связан с посещённым мероприятием; ввод можно пропустить без записи. |
| FB-03 | Оставить общий отзыв | Участник | Не связан с мероприятием и не меняет настройку автоматических предложений. |
| FB-04 | Просмотреть отзывы | Администратор | Постраничная таблица и просмотр полного текста; видны автор, время и мероприятие или признак общего отзыва. |
| STATS-01 | Просмотреть статистику людей | Администратор | Пагинация и сортировки: ФИО, число посещений, последнее посещение. Отзывы включают связанные и общие. |

### Критические инварианты первого среза

1. Время регистрации, отмены, ответа о посещении и отзыва никогда не
перезаписывается отображаемой строкой времени; хранится исходный timestamp.
2. Регистрация уникальна по `event_id + person_id`; её состояние меняется
явно, а не удалением строки.
3. Общий отзыв имеет `event_id = NULL`; это не ошибка и не ссылка на последнее
мероприятие.
4. Проверка прав выполняется до чтения чужих данных. Наличие Telegram ID само
по себе не делает пользователя администратором.
5. Сохранённая отметка посещения не откатывается, если отправка предложения
отзыва в Telegram завершилась ошибкой.

## Публикации и доставка Telegram

| ID | Use case | Актор | Основные правила |
| --- | --- | --- | --- |
| PUB-01 | Создать черновик | Администратор | Текст, ссылки, фотография, альбом или Telegram Rich Message. Видео, документы и опросы вне scope. |
| PUB-02 | Выбрать Telegram-цели | Администратор | Канал, чат или конкретный топик супергруппы; целью владеет конфигурация deployment. |
| PUB-03 | Опубликовать или запланировать | Администратор | Немедленная либо отложенная публикация в `TIMEZONE`; максимум пять ожидающих публикаций. |
| PUB-04 | Отменить ожидающую публикацию | Администратор | Не изменяет уже опубликованные сообщения. Массовое удаление и редактирование не входят в scope. |
| PUB-05 | Доставить публикацию | Delivery worker | Отдельный результат на каждую Telegram-цель, retries для временных ошибок, уведомление создателю. |
| PUB-06 | Завершить публикацию | Delivery worker | После всех доставок сформировать итоговое уведомление и освободить временные медиа. |

**VK намеренно исключён.** В этом каталоге нет use case, delivery target,
переменной окружения или migration path для VK.

## Материалы разговорного клуба

| ID | Use case | Актор | Основные правила |
| --- | --- | --- | --- |
| LRN-01 | Настроить генерацию | Администратор | Выбрать JLPT N5–N1 и необязательное пожелание. |
| LRN-02 | Создать черновик материала | Администратор или Scheduler | Структура: тема, вопросы, лексика, грамматика; материал валидируется до сохранения. |
| LRN-03 | Просмотреть, перегенерировать или исправить материал | Администратор | Создаётся новая версия, история и время запланированной публикации сохраняются по правилам use case. |
| LRN-04 | Одобрить материал и поставить в очередь | Администратор | Создаёт заявку Publishing только после успешной валидации. |
| LRN-05 | Ежедневно подготовить материал | Scheduler | Политика `manual_review` или `auto_publish`; идемпотентность по дате и настройке. |
| LRN-06 | Поддерживать историю разнообразия | Модуль материалов | История влияет на prompt, но не вводит жёсткий запрет на повтор лексики или грамматики. |

Ошибка AI, в том числе превышение длины ответа, не создаёт пустую публикацию:
она остаётся ошибкой generation job, получает retry policy и уведомление
администраторам после исчерпания попыток.

## Будущая граница

`Language Practice` будет обрабатывать японскую орфографию только для точно
настроенной пары `chat_id + message_thread_id`. Это отдельный use case и не
является обработкой каждого сообщения Telegram или частью `Learning Content`.
